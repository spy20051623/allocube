# Allocube

Allocube 是面向内部团队的计算资源占用系统。它将机器上的逻辑核、GPU、内存等资源组合成可预约的资源组，为多人共享紧张计算资源提供权限申请、占用排期、冲突处理、停用管理、通知和统计能力。

系统只登记资源的计划占用时间，不控制 SSH、操作系统账号、进程或硬件，也不采集真实 CPU、GPU、内存利用率。

## 主要功能

### 用户与权限

- 用户使用唯一用户名注册，并提供姓名、工号、邮箱和密码。
- 注册前验证邮箱，注册资料由系统管理员审核。
- 登录支持用户名或已启用工号；邮箱只用于验证、通知和密码找回。
- 用户可维护用户名、姓名、工号、邮箱、密码、邮件偏好和自动登出时长。
- 每台机器单独管理使用权；用户可申请，管理员也可直接邀请。
- 机器管理员与机器绑定，只能管理被授权机器；机器管理员只能由系统管理员设置。
- 系统管理员、机器管理员和普通用户看到的信息与可执行操作按权限裁剪。

### 资源模型

- 机器可配置三类资源项：
  - 编号范围，例如逻辑核 `0–127`。
  - 独立设备，例如 GPU 0、GPU 1。
  - 可切分容量，例如 512 GiB 内存。
- 一个资源组可以组合多种资源。
- 资源分配默认独占，也支持容量等共享资源。
- 保存资源配置时统一检查范围、设备重复、容量超限和资源组冲突。
- 资源项和资源组支持拖动排序、配置版本与历史快照。

### 资源占用

- 资源日历支持按机器折叠、日期跳转、6/12/24小时缩放和横向滚动。
- 支持资源组占用和整机占用，两种模式互斥。
- 拖动时间轴即可创建草稿；系统会避开过去时间和已有冲突，并合并相邻草稿。
- 占用详情、浏览和编辑使用一致的交互；编辑在最终提交前不会修改服务端记录。
- 最终提交在事务中重新检查冲突，任一时段失效则本次提交不生效。
- 支持未来占用修改、取消，以及进行中占用的剩余时间调整或提前结束。
- 机器管理员可以释放所管理机器上的占用。

### 管理与通知

- 机器和资源组支持计划停用、长期停用、重新启用与永久删除。
- 停用前预览受影响占用，可按交集取消、裁切或拆分。
- 用户管理、机器权限申请和资料修改均支持并发版本校验。
- 提供站内通知、未读计数、一键已读和按事件跳转。
- SMTP 使用持久化发件箱，支持失败重试及验证码、密码重置邮件过期。
- 系统管理员可在线配置站点地址、注册邮箱白名单、占用规则和 SMTP。
- 提供占用统计、CSV 导出和审计记录。
- 已删除的用户、机器或资源在必要历史记录中使用去标识化名称展示。

## 技术架构

- 前端：React、TypeScript、Vite、TanStack Router。
- 服务端：Fastify、TypeScript。
- 数据库：SQLite、`better-sqlite3`，启用 WAL、外键和写入超时。
- 邮件：Nodemailer，支持隐式 SSL/TLS 和 STARTTLS。
- 部署：单个 Node.js 应用实例，Caddy 提供 HTTPS，Docker Compose 管理应用和备份。

生产构建后，Fastify 在一个端口同时提供静态页面和 `/api/v1` 接口。SQLite 只支持单应用实例；需要横向扩容前必须先迁移到 PostgreSQL 等独立数据库。

## 本地开发

### 环境要求

- Node.js 22 或更新的受支持版本。
- npm。

### 启动

```text
npm ci
npm run dev
```

打开 `http://localhost:5173`。不要混用 `localhost`、`127.0.0.1` 和其他局域网地址访问同一个会话，否则浏览器的同源安全检查可能拒绝修改请求。

开发模式会启动两个进程：

- `5173`：Vite 开发页面和热更新服务，对浏览器开放。
- `8787`：Fastify API，由 Vite 代理访问。

这两个端口只是开发工具分工。生产构建由一个 Node.js 进程同时提供页面和 API。

本地开发允许 HTTP。首次使用全新数据库时会创建系统管理员：

- 用户名：`Administrator`
- 默认密码：`Admin12#$`

登录页不会自动填充账号或密码。默认密码只用于本地开发；生产部署必须通过首次启动配置设置随机强密码。系统不会强制跳转修改密码，但会持续显示安全提醒。

开发环境默认创建演示机器、资源项、资源组和用户。生产环境默认不创建演示数据。

### 配置模型

如需覆盖开发默认值，可将 `.env.example` 复制为 `.env`。配置分为“每次启动读取”和“仅首次初始化读取”两类，不应混用。

#### 每次启动读取

这些配置决定当前进程如何运行，每次启动都会读取：

| 配置 | 作用 |
|---|---|
| `NODE_ENV` | 选择开发或生产运行模式；正式部署必须使用 `production` |
| `HOST` | 指定 Fastify 监听地址；仅在明确需要从其他主机访问开发服务时调整 |
| `PORT` | 指定 Fastify 监听端口 |
| `DATABASE_PATH` | 指定 SQLite 主数据库的位置 |

Docker Compose 还会读取 `APP_DOMAIN`，用于配置 Caddy 的正式域名和 HTTPS 证书。它不属于应用内的持久设置。

#### 仅首次初始化读取

`BOOTSTRAP_*` 配置只在数据库为空时读取一次。初始化结果会写入数据库；之后修改环境文件或重启服务，不会覆盖管理员在系统内保存的设置。

| 初始化内容 | 对应配置 | 作用 | 初始化后的管理方式 |
|---|---|---|---|
| 管理员姓名 | `BOOTSTRAP_ADMIN_NAME` | 设置 Administrator 的初始姓名 | 作为初始管理员资料保留 |
| 管理员密码 | `BOOTSTRAP_ADMIN_PASSWORD` | 设置 Administrator 的初始登录密码 | 用户信息中修改，或使用服务器恢复命令 |
| 站点地址 | `BOOTSTRAP_SITE_ORIGIN` | 设置邮件链接使用的对外访问地址 | 系统设置 |
| 注册邮箱白名单 | `BOOTSTRAP_ALLOWED_EMAIL_DOMAINS` | 限制允许注册的邮箱域名 | 系统设置 |
| 最短占用时间 | `BOOTSTRAP_MIN_BOOKING_MINUTES` | 限制单次占用允许的最短时长 | 系统设置 |
| 单次最长占用时间 | `BOOTSTRAP_MAX_BOOKING_MINUTES` | 限制单次占用允许的最长时长 | 系统设置 |
| 最远可预约时间 | `BOOTSTRAP_ADVANCE_DAYS` | 限制用户可以提前预约到多少天之后 | 系统设置 |
| 演示数据 | `BOOTSTRAP_DEMO_DATA` | 决定首次初始化时是否创建演示机器和用户 | 仅初始化时决定 |
| 邮件发送 | `BOOTSTRAP_SMTP_*` | 初始化 SMTP 连接和发件人信息 | 系统设置 |

邮箱白名单在环境变量中使用英文逗号分隔，不带 `@`，例如 `company.com,subsidiary.cn`。

SMTP 引导配置只有在服务器、账号、密码和发件邮箱全部提供时才会采用；只填写其中一部分会被视为配置错误并阻止初始化。通常保持停用并在管理员登录后在线配置更直观。

## 常用命令

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动开发页面和 API |
| `npm run typecheck` | 检查前后端 TypeScript 类型 |
| `npm test` | 运行自动测试 |
| `npm run build` | 生成生产页面和服务端代码 |
| `npm start` | 运行已经构建的服务 |
| `npm run backup` | 创建 SQLite 在线备份 |
| `npm run db:reset` | 删除并重建当前调试数据库，属于破坏性操作 |
| `npm run admin:reset-password` | 在服务器端恢复 Administrator 密码 |

健康检查地址为 `/health`，内部 JSON API 统一使用 `/api/v1`。

## 数据文件

数据库默认位于 `data/allocube.sqlite`，采用 WAL 模式。SQLite 文件必须放在服务器本机持久磁盘，不得放在 NFS、SMB 等网络文件系统中。

应用首次启动时会在数据库旁创建 `instance-secrets.json`，其中保存：

- 会话 Cookie 签名密钥。
- SMTP 密码加密密钥。

该文件和数据库、`-wal`、`-shm`、备份文件、`.env`、`.env.production` 均不得提交到代码仓库。仓库中的忽略规则已覆盖这些文件，但提交前仍应检查待提交内容。

## 邮件配置

系统管理员在“管理 → 系统设置 → 邮件发送”中配置 SMTP：

- SMTP 服务器和端口。
- SSL/TLS 或 STARTTLS。
- 登录账号和密码。
- 发件人名称和发件邮箱。
- 测试邮件收件地址。

SMTP 密码使用 AES-256-GCM 加密后写入数据库，接口、审计和页面不会返回密码明文。修改配置后无需重启服务。

邮件中的查看与密码重置链接使用“系统设置 → 站点地址”。开发环境允许本机 HTTP 地址；生产环境只接受不带业务路径的 HTTPS 地址。

邮件服务停用时，不会创建新的邮件任务；站内通知仍正常工作。依赖邮件的注册验证码和密码找回会提示服务暂不可用。

## 单机生产部署

### 部署前准备

1. 准备一个解析到服务器的域名。
2. 在防火墙或安全组开放 TCP 80 和 443。
3. 安装 Docker 与 Docker Compose。
4. 将 `.env.production.example` 复制为 `.env.production`。
5. 至少填写：
   - `APP_DOMAIN=allocube.your-company.com`
   - `BOOTSTRAP_ADMIN_PASSWORD=随机生成的强密码`
   - `BOOTSTRAP_SITE_ORIGIN=https://allocube.your-company.com`
6. 在 Linux 上执行 `chmod 600 .env.production`。

不要把 `.env.production`、真实域名、邮箱账号、SMTP 密码、内网地址或其他本地配置提交到代码仓库。

### 启动

```text
docker compose --env-file .env.production up -d --build
```

Caddy 会将 HTTP 永久跳转到 HTTPS，并自动申请和续期证书。应用容器的 `8787` 端口只用于容器内部通信，不应通过 Docker 端口映射、防火墙或云安全组暴露到公网。

部署完成后：

1. 打开 `https://你的域名`。
2. 使用 Administrator 登录并修改初始密码。
3. 在系统设置中确认站点地址。
4. 配置注册邮箱白名单和占用规则。
5. 配置 SMTP 并发送测试邮件。
6. 检查 `/health`、注册、登录、邮件和备份。

生产环境启用 HTTPS 强制、安全 Cookie、来源校验、CSRF 校验、限流和严格安全响应头。不要使用开发服务代替生产部署验收。

### 更新

更新代码前先创建备份，然后重新构建并启动：

```text
docker compose --env-file .env.production run --rm backup node scripts/backup.mjs
docker compose --env-file .env.production up -d --build
```

如果新版本包含数据库迁移，应用会在启动时执行迁移；迁移失败时不要反复删除数据卷，应保留日志和备份进行排查。

## 备份与恢复

`backup` 服务会在启动后执行在线备份，之后默认每24小时执行一次：

- `BACKUP_INTERVAL_SECONDS`：备份间隔，默认 `86400`。
- `BACKUP_RETENTION_DAYS`：保留天数，默认 `14`。

立即创建在线备份：

```text
docker compose --env-file .env.production run --rm backup node scripts/backup.mjs
```

备份完成后会执行 SQLite 完整性和结构版本检查，校验失败的文件不会保留。数据库备份包含账号、占用、通知和审计信息，复制到异地前应再次加密。

必须单独安全备份数据卷中的 `instance-secrets.json`，并与数据库备份、备份解密凭据分开保管。数据库备份本身不能解密 SMTP 密码。

恢复步骤：

1. 停止应用和备份容器。
2. 保留当前数据库作为回滚副本。
3. 将选定备份恢复为数据卷中的 `allocube.sqlite`。
4. 将对应实例的 `instance-secrets.json` 恢复到同一目录。
5. 限制密钥文件只允许运行用户读取。
6. 确认同目录不存在来自另一数据库版本的旧 `-wal` 和 `-shm` 文件。
7. 重新启动应用，检查 `/health` 并执行登录、邮件和关键数据抽查。

如果 `instance-secrets.json` 遗失，应用可以生成新密钥并启动，但现有会话、未使用验证码和已保存 SMTP 密码会失效；管理员需要重新登录并重新输入 SMTP 密码。

永久删除操作不会修改删除前已经生成的备份。旧备份和人工复制的备份仍必须按保留策略到期清理。

## 安全说明

- 密码使用 Argon2id 哈希，密码、验证码和会话令牌不会以明文保存。
- 登录会话使用服务端记录和 HttpOnly Cookie。
- 修改请求实施同源、CSRF 和来源检查。
- 登录、验证码、注册和密码找回实施限流。
- 生产环境拒绝 HTTP 业务请求，必须通过受信任反向代理使用 HTTPS。
- SMTP 只允许加密连接，不支持忽略证书错误或明文中继。
- 数据库查询使用参数绑定，结构化输入在前后端重复校验。
- 页面输出和邮件模板对用户内容进行转义或结构化渲染。
- 审计记录关键管理操作，但不记录密码、密文和管理备注正文。

发现“请求来源不受信任”时，通常是页面与 API 使用了不同的协议、域名或端口，或反向代理没有正确传递 `Host`、`X-Forwarded-Host` 和 `X-Forwarded-Proto`。不要关闭来源检查，应修复访问地址或代理配置。

## 当前边界

- 首版为中文桌面端界面，时间以 `Asia/Shanghai` 展示。
- 占用时间精确到分钟，区间采用左闭右开 `[start, end)`。
- 不支持周期占用、候补队列、项目配额或占用审批。
- 不控制真实机器账号、SSH 权限、进程和硬件。
- 统计来自登记占用时段，不代表真实硬件使用率。
- SQLite 部署只允许单个应用实例。

角色界面术语和信息边界见 [角色化界面语言](docs/role-aware-language.md)。
