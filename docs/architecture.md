# 代码组织与维护边界

Allocube 继续使用单个 Fastify 应用和 SQLite 数据库。本轮重构不改变 URL、API 字段、权限或数据库结构。

## 前端

| 位置 | 职责 |
| --- | --- |
| `src/App.tsx` | 页面选择、应用布局和全局能力装配 |
| `src/app/` | 会话、提示消息、全局输入行为、冲突对话框与请求的衔接 |
| `src/components/` | 表单、密码输入、弹窗、标签编辑、操作反馈等跨功能组件 |
| `src/features/` | 按业务组织的页面、局部组件、控制 Hook 和专属类型 |
| `src/shared/` | 前后端共用的契约与规则；新增模块不依赖页面、HTTP 框架或数据库 |

已有的 `PageHeader`、`Modal`、`SelectControl`、日期工具和实时刷新模块继续复用。公共组件不能导入业务页面；业务模块不能导入 `App` 或应用外壳。功能之间需要共用逻辑时，先检查现有公共模块，再确定归属，避免通过另一个页面获取工具函数。

设置页的展示与 `useSettingsController` 分开，后者负责读取、保存、重试、草稿保护和结果不确定状态。日历由 `useCalendarController` 协调草稿与预约操作，`useTimelineData` 负责加载和索引，`useDragAutoScroll` 负责动画帧生命周期，事件、轨道、字段和弹层分别展示。

不要把所有表单合并为一种状态模型。设置、预约和反馈各自已有版本、预览或附件语义，继续复用底层请求门控和冲突机制。

## 后端

`registerAdminRoutes` 只装配用户、机器、访问权、资源配置、维护停用、SMTP、系统设置、报表和审计路由。`server/admin/` 中的路由负责鉴权、参数解析与 HTTP 响应；服务模块负责领域操作，不能依赖 Fastify 或路由模块。

普通设置更新通过 `updateAdminSettings` 在同一立即事务内完成版本检查、单项写入、版本递增和审计。写入或审计失败时全部回滚；显式覆盖仍执行字段校验。SMTP 保留自己的版本、加密密码和发送队列处理。

预约预览与批量提交共用请求 Schema 和互斥参数规则。鉴权顺序保持在各自入口，预约服务继续由网页接口和官方 API 共用；官方 API 的预确认、令牌权限和重放处理留在其适配层。

## 样式与小型交互调整

`src/styles.css` 是有顺序的样式入口，功能样式和共用样式按原有级联顺序加载。部分跨功能规则仍相邻存放，避免仅为目录整齐改变优先级。新增样式优先归入所属功能或公共组件；调整导入顺序时必须验证覆盖效果。

可以在重构中统一已有控件、反馈和表单交互。每项可见调整独立提交，并说明变化与验证结果。不要借结构迁移改变字段含义、时区、操作触发时机或权限。

本轮将 SMTP 测试和保存按钮接入现有 `BusyButtonContent`，统一等待动画与标签占位，并为保存按钮保留稳定的无障碍名称。按钮禁用条件、提交内容与保存流程不变；通过设置网络回归和中英文窄屏检查验证。

## 验证

- `npm run typecheck`、`npm test` 和 `npm run build` 检查类型、功能与产物。
- 模块边界测试阻止反向依赖和前端循环依赖；复用约束检查实际功能模块，不要求组件留在入口文件。
- 编辑冲突、设置网络、日历调整和实时 HTTP 脚本覆盖草稿、断网、并发、导航与权限变化。
- 管理接口测试共用隔离数据库及登录辅助函数；必须先配置环境再导入数据库模块，继续串行执行。

结构迁移、业务去重和可见交互调整分别提交，便于定位回归和按批回滚。
