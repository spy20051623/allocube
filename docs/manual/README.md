# 产品介绍

Allocube 是面向内部团队的计算资源占用系统。它把机器上的逻辑核、GPU、内存等资源整理为可占用的资源组，帮助团队在共享计算资源时明确权限、排期和变更记录。

> Allocube 只记录计划占用，不控制 SSH、操作系统账号、进程或硬件，也不采集真实 CPU、GPU、内存利用率。

## 角色和权限

| 角色 | 主要能力 |
|---|---|
| 普通用户 | 浏览公开机器、申请使用权、查看已授权资源、管理自己的占用和“用户信息” |
| 机器管理员 | 在普通用户能力基础上，管理被授权机器的配置、成员、使用权申请、维护和占用释放 |
| 系统管理员 | 管理全部用户、机器、资源、系统公告、“系统设置”、统计和审计 |

机器管理员身份按机器授予。一个用户可以管理部分机器，同时只是其他机器的普通使用者。

## 核心概念

### 机器

机器是权限、资源配置和排期的边界。用户必须拥有一台机器的有效使用权，才能占用它的资源。

### 资源项和资源组

资源项支持编号范围、独立设备和可切分容量三种模型。资源组把一个或多个资源项组合成可占用单元，例如“CPU 0–15 + GPU 0 + 64 GiB 内存”。

### 占用范围

- **资源组占用**：只锁定指定资源组及其分配。
- **整机占用**：锁定机器的全部资源，与同一机器上的资源组占用互斥。

### 时间

时间精确到分钟，区间采用左闭右开 `[start, end)`。例如 `10:00–11:00` 与 `11:00–12:00` 可以相邻存在。

## 文档占位符约定

文档中所有必须由读者替换的值，统一写成 `<UPPER_SNAKE_CASE>`，例如 `<BASE_URL>`、`<API_TOKEN>` 和 `<MACHINE_ID>`。

- 使用示例前，必须用真实值替换整个占位符，包括两侧尖括号。
- 同名占位符始终表示同一种值；不同名称不能互换。
- OpenAPI 路径中的 `{id}` 是标准路径参数语法。实际请求时应把它替换为对应资源 ID；可复制示例使用 `<MACHINE_ID>`、`<RESERVATION_ID>` 等明确名称。
- Shell 中的 `$NAME` 或 `${NAME}` 表示环境变量引用，不是文档占位符。环境变量自身的示例赋值仍使用 `<UPPER_SNAKE_CASE>`。
- 没有尖括号的日期、标题和枚举值是说明性示例，可以直接满足格式约束，但仍应按实际业务修改。

常用占位符：

| 占位符 | 应替换为 |
|---|---|
| `<BASE_URL>` | Allocube 的完整访问来源，例如协议、域名和可选端口，不带末尾斜杠 |
| `<ALLOCUBE_DOMAIN>` | 不含协议和路径的 Allocube 访问域名 |
| `<API_TOKEN>` | 在“用户信息”中创建后只显示一次的个人访问令牌 |
| `<CONFIRMATION_TOKEN>` | 同一次成功预检响应中的 `confirmationToken` |
| `<MACHINE_ID>` | 机器 UUID |
| `<MACHINE_IDS>` | 使用英文逗号分隔的一个或多个机器 UUID |
| `<RESOURCE_GROUP_ID>` | 资源组 UUID |
| `<RESERVATION_ID>` | 本人占用 UUID |
| `<CURSOR>` | 上一页 `meta.nextCursor` 返回的不透明字符串 |
| `<START_AT_RFC3339>` / `<END_AT_RFC3339>` | 实际占用的 UTC RFC 3339 开始和结束时间 |
| `<REQUEST_ID>` | 实际响应中的请求追踪 ID，仅用于展示响应示例或问题定位 |
| `<ADMIN_PASSWORD>` | 部署者生成的管理员强密码 |
| `<ALLOWED_EMAIL_DOMAINS>` | 使用英文逗号分隔的注册邮箱域名 |
| `<SMTP_HOST>` | SMTP 服务器主机名 |
| `<SMTP_USERNAME>` / `<SMTP_PASSWORD>` | 实际 SMTP 登录凭据 |
| `<SMTP_FROM_ADDRESS>` | 实际发件邮箱地址 |

## 产品边界

- 不提供周期占用、候补队列、项目配额或占用审批。
- 统计基于系统登记的占用时段，不代表真实硬件利用率。
- 机器使用权不等于操作系统账号或网络访问权。
- 已删除对象可能继续以去标识化名称出现在历史占用和审计记录中。
