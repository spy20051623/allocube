# Product introduction

Allocube helps internal teams reserve shared computing resources. It organizes logical cores, GPUs, memory, and other machine resources into bookable groups, with clear access rules, schedules, and change history.

> Allocube only records planned reservations; it does not control SSH, OS accounts, processes, or hardware, nor does it collect actual CPU, GPU, or memory utilization metrics.

## Roles and permissions

| Role | Main capabilities |
|---|---|
| Regular user | Browse machines, request access, view authorized resources, manage personal reservations and the "Profile" page |
| Machine administrator | All regular user capabilities, plus manage configuration, members, access requests, maintenance, and reservation releases for authorized machines |
| System administrator | Manage all users, machines, resources, announcements, "Settings", reports, and audit logs |

Machine administrator status is granted per machine. A user can manage some machines while being a regular user for others.

## Core concepts

### Machine

A machine is the boundary for permissions, resource configuration, and scheduling. Users need access to a machine before they can reserve its resources.

### Resource items and resource groups

Resource items support three models: numbered ranges, independent devices, and divisible capacity. A resource group combines one or more resource items into a reservable unit, e.g., "CPU 0–15 + GPU 0 + 64 GiB Memory".

### Reservation scope

- **Resource Group Reservation**: Locks only the specified resource group and its allocations.
- **Machine Reservation**: Reserves the entire machine and cannot overlap a resource group reservation on that machine.

### Time

Reservations use one-minute precision. Intervals are left-closed and right-open: `[start, end)`. This allows `10:00–11:00` and `11:00–12:00` to run back-to-back.

## Documentation placeholder convention

Replaceable values are written as `<UPPER_SNAKE_CASE>`, for example `<BASE_URL>`, `<API_TOKEN>`, and `<MACHINE_ID>`.

- Before using an example, you must replace the entire placeholder, including the angle brackets, with the real value.
- Identically named placeholders always represent the same type of value; different names are not interchangeable.
- The `{id}` in OpenAPI paths is standard path parameter syntax. In actual requests, replace it with the corresponding resource ID; copyable examples use explicit names like `<MACHINE_ID>`, `<RESERVATION_ID>`, etc.
- `$NAME` or `${NAME}` in shell commands represents environment variable references, not documentation placeholders. Example assignments for the environment variables themselves still use `<UPPER_SNAKE_CASE>`.
- Dates, titles, and enum values without angle brackets are examples. Replace them with values appropriate for your request.

Common placeholders:

| Placeholder | Should be replaced with |
|---|---|
| `<BASE_URL>` | The full access origin for Allocube, e.g., protocol, domain, and optional port, without a trailing slash |
| `<ALLOCUBE_DOMAIN>` | The Allocube access domain without protocol or path |
| `<API_TOKEN>` | The personal access token created under "Profile → API tokens", shown only once |
| `<CONFIRMATION_TOKEN>` | The `confirmationToken` from the same successful preflight response |
| `<MACHINE_ID>` | Machine UUID |
| `<MACHINE_IDS>` | One or more machine UUIDs, separated by commas |
| `<RESOURCE_GROUP_ID>` | Resource Group UUID |
| `<RESERVATION_ID>` | Own reservation UUID |
| `<BATCH_ID>` | Reservation batch UUID generated by the same CREATE submission |
| `<CURSOR>` | The opaque string returned by the previous page's `meta.nextCursor` |
| `<START_AT_RFC3339>` / `<END_AT_RFC3339>` | The actual reservation's UTC RFC 3339 start and end times |
| `<REQUEST_ID>` | The request trace ID from the actual response, used only for displaying response examples or issue diagnosis |
| `<ADMIN_PASSWORD>` | The strong administrator password generated by the deployer |
| `<ALLOWED_EMAIL_DOMAINS>` | Allowed registration email domains, separated by commas |
| `<SMTP_HOST>` | SMTP server hostname |
| `<SMTP_USERNAME>` / `<SMTP_PASSWORD>` | Actual SMTP login credentials |
| `<SMTP_FROM_ADDRESS>` | Actual sender email address |

## Product boundaries

- Does not provide recurring reservations, waitlists, project quotas, or reservation approval workflows.
- Statistics are based on system-recorded reservation periods and do not represent actual hardware utilization.
- Machine access does not equate to OS account or network access rights.
- Deleted objects may continue to appear in historical reservations and audit logs under de-identified names.
