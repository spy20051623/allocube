# 部署与运维

Allocube 使用单个 Node.js 进程提供页面和 API，并使用 SQLite 保存数据。SQLite 部署只支持单应用实例。

## 运行要求

- Node.js 22 或更新的受支持版本。
- 本地持久磁盘；不要把 SQLite 文件放在 NFS、SMB 等网络文件系统。
- 生产环境建议由 Caddy 或其他反向代理提供域名和 TLS。

## 本地开发

```text
npm ci
npm run dev
```

开发页面默认运行在 `http://localhost:5173`，Fastify API 默认运行在 `127.0.0.1:8787` 并由 Vite 代理。不要混用 `localhost`、`127.0.0.1` 和其他地址访问同一会话。

## 生产构建

直接运行 Node.js 服务时，先在进程环境或工作目录的 `.env` 中设置 `NODE_ENV=production`；首次部署还必须设置 `BOOTSTRAP_ADMIN_PASSWORD`。例如 `.env` 的最小配置：

```dotenv
NODE_ENV=production
BOOTSTRAP_ADMIN_PASSWORD='<ADMIN_PASSWORD>'
```

替换密码占位符后再运行下列命令。`npm run build` 和 `npm start` 不会自动把运行模式设为生产。服务自动读取工作目录的 `.env`，已有进程环境变量优先；直接运行时不会自动读取 `.env.production`，后者由下文 Docker Compose 加载。

```text
npm ci --include=dev
npm run build
npm start
```

生产构建由 Fastify 在一个端口同时提供静态页面和 API。构建需要开发依赖，因此即使安装时已设置 `NODE_ENV=production`，也要使用 `--include=dev`。

## 首次初始化

全新数据库只创建初始化配置和 Administrator 账号，不自动生成机器、资源组、演示用户或示例占用。`BOOTSTRAP_DEMO_DATA` 已移除；升级不会自动删除已有数据。首次看到空日历是正常情况，应由系统管理员创建机器和资源组。验收数据应放在独立测试数据库中。

每次启动读取：

- `NODE_ENV`
- `HOST`
- `PORT`
- `DATABASE_PATH`

`BOOTSTRAP_*` 只在空数据库首次初始化时读取，包括管理员资料、站点地址、占用规则和 SMTP。之后修改环境变量不会覆盖数据库中的管理设置。

生产首次初始化必须为 `BOOTSTRAP_ADMIN_PASSWORD` 显式设置随机强密码，并保护 `.env.production`。未设置、空值、旧默认管理员密码或不符合现有密码规则的值都会导致服务以非零状态退出，不开放 HTTP 端口。密码须为 8–64 位可打印半角字符，不含空格，包含字母和数字，且不能是常见密码或管理员用户名；服务不会自动修剪或改写输入。

密码校验失败后可能留下空数据库结构和实例密钥，但不会写入管理员、持久配置或初始化完成标记。修正密码后使用原数据目录重新启动即可，无需删除数据库或密钥。开发与测试环境保留原有默认初始化行为。

已初始化实例升级后无需补填此变量，也不会重新校验或覆盖已有管理员密码。本次修复不会消除已有实例的默认密码风险，运维人员仍需自行确认并更换；正常情况下登录后修改密码，无法登录时使用下文“管理员密码恢复”的服务器端命令。修改 `BOOTSTRAP_ADMIN_PASSWORD` 不会重置已有账号密码。

部署配置中的待替换值同样使用统一占位符格式。例如：

```dotenv
APP_DOMAIN=<ALLOCUBE_DOMAIN>
BOOTSTRAP_ADMIN_PASSWORD='<ADMIN_PASSWORD>'
BOOTSTRAP_SITE_ORIGIN=<BASE_URL>
```

复制后必须替换整个 `<PLACEHOLDER_NAME>`；不要把占位符原样用于生产启动。

## Docker Compose

首次部署先将 `.env.production.example` 复制为 `.env.production`，填写域名和管理员强密码，再启动。已有部署沿用原数据卷和配置文件。

```text
docker compose --env-file .env.production up -d --build
```

应用容器端口只用于容器内部通信，不应直接映射到公网。反向代理需要正确传递 `Host`、`X-Forwarded-Host` 和 `X-Forwarded-Proto`。

重复构建生产镜像时使用仓库内的缓存构建脚本：

```text
sh scripts/build-docker-release.sh RELEASE_ID BUILD_CONTEXT
```

脚本将依赖层保存为具名 Docker 镜像，并默认在 `/opt/allocube-build-cache` 保留按依赖输入区分、同时包含 Node 基础镜像的离线归档。每次构建先查找对应归档和镜像：命中时断网复用；确实没有时自动联网补齐一次，并立即写回该目录，下一次构建继续复用。依赖输入包括 `package.json`、`package-lock.json`、`Dockerfile`、基础镜像名称和软件源配置，避免错误复用或无故失效。清理 Docker 镜像时不得删除 `allocube-build-cache:*`，离线归档也应纳入服务器磁盘备份。

缓存目录可通过 `ALLOCUBE_BUILD_CACHE_DIR` 修改，目录需可写；离线归档包含 `.tar` 和配套 `.manifest`。仅修改业务代码可复用依赖缓存，依赖输入变化或缓存丢失时需要联网补齐。缓存脚本默认使用阿里云 Debian 镜像，可通过 `DEBIAN_MIRROR`、`DEBIAN_SECURITY_MIRROR` 调整；直接 Docker 构建默认使用 Debian 官方源。镜像内已安装原生模块构建需要的 Python、make 和 C++ 编译器。

## 健康检查

```text
GET /health
```

正常时返回 `200` 和 `{"status":"ok"}`。数据库不可用时返回 `503`。

## 数据文件

主数据库默认为 `data/allocube.sqlite`，私有反馈图片位于同一持久化数据卷的 `data/feedback-images`，旁边的 `instance-secrets.json` 保存会话密钥和 SMTP 加密密钥。数据库、图片、WAL、SHM、实例密钥、备份和环境文件都不得提交到代码仓库；`feedback-images` 不能映射为公开静态目录。

## 备份与恢复

```text
npm run backup
```

备份使用 SQLite 在线备份并执行完整性和结构版本检查。命令会创建一个时间戳备份集，其中包含 `allocube.sqlite`、该数据库快照引用的有效 `feedback-images` 图片和 `manifest.json`。清单记录文件数量、总大小和每个文件的 SHA-256；任一有效图片缺失或大小不符时整次备份失败，不会发布不完整备份集。应同时安全备份：

- 完整的数据库加反馈图片备份集。
- `instance-secrets.json`。
- 备份加密凭据和部署配置。

实例密钥应与备份集分开保管。恢复时先停止应用并保留故障现场，验证 `manifest.json` 中全部 SHA-256 后，再按同一版本程序将数据库、`feedback-images` 和实例密钥作为一个整体恢复。不得将一份数据库与另一时间点的图片目录混用。

## 升级与回滚

1. 阅读目标版本的数据库迁移说明。
2. 生成并校验数据库加反馈图片备份集，另行备份实例密钥。
3. 构建并启动新版本。
4. 检查 `/health`、登录、“资源日历”、反馈创建与图片读取权限、通知红点、图片持久化、写操作、邮件和备份清单。

当前数据库结构版本为 22，启动时会自动执行适用的迁移。近期涉及：

| 版本 | 变化 |
|---|---|
| 17 | 反馈工单及私有图片 |
| 18 | 站内通知的翻译模板与参数 |
| 19 | 管理员超时审核邮件的去重记录 |
| 20 | 每日使用统计、统计版本与全量重算任务 |
| 21 | 审计查询索引 |
| 22 | 机器公告正文，现有机器默认为空 |

此前的“我的占用”重构与生产初始化密码修复未新增数据库结构。升级后应检查日历编辑序列的整批提交、旧 `/reservations` 链接跳转，以及管理员审核提醒。现有实例无需补填初始化密码；此前的默认密码风险仍需自行排查。

网页内部 `/api/v1/reservations/mine` 已改为分类查询、筛选和游标分页，默认只返回未开始占用。曾直接调用旧内部接口的脚本需适配，建议迁移到官方 `/api/open/v1`；本轮未改变官方 API 契约。

数据库升级后，旧程序可能无法读取新结构。特别是结构版本 17 引入反馈数据和私有图片，回滚必须同时恢复升级前数据库、与其配套的图片备份、实例密钥和旧镜像，不能只回滚程序文件。

## 每日统计任务

升级到版本 20 后，服务先开放 HTTP，再由单个后台 Worker 使用独立 SQLite 连接补算历史。无需配置系统 cron；运行期间每分钟检查北京时间 06:00 的结算条件，停机遗漏自动补算。日常计算失败后间隔 5 分钟重试，不阻断主服务启动。

统计快照、日期完成标记和重算进度都在同一个 SQLite 数据库中，现有备份自动包含它们。恢复或重启后继续未完成日期，不重复计入。全量重算使用独立统计版本，成功后整体切换，失败保留旧结果；失效构建按日期清理。重算期间需要额外磁盘空间容纳新旧两份统计数据。

日志包含完成日期、耗时及失败原因；审计记录包含全量重算发起人、范围及成败。后台统计不修改日历排期版本，不发送占用通知。不要手动删除统计表来修复失败；先检查磁盘、权限和日志，再在“使用统计”中重新发起全量重算。

内部 `/api/v1/admin/report` 改用包含首尾日期的 `fromDate`、`toDate`（`YYYY-MM-DD`），旧 ISO 时间参数不再接受。CSV 导出功能及内部 `/api/v1/admin/report.csv` 接口已移除。新增全量重算及任务状态内部接口；官方 `/api/open/v1` 契约不变。升级前备份，回滚时恢复版本 19 的完整备份及配套程序。

## 实时更新与验收

网页继续使用 `/api/v1/events` 的 SSE 连接。内部 `revision` 事件保留排期版本，新增协议版本、独立事件标识及数据类别、机器和时间范围；权限变化可能不递增排期版本。事件按当前权限投递，撤权通知仍发送给失权用户，只包含刷新标识，不包含占用说明或用户资料。公告、反馈的投递规则和使用统计的结算、任务查询频率不变，官方 `/api/open/v1` 契约不变。

服务在主 SQLite 连接上通过临时触发器收集事务内的前后变化，仅在提交后发布；回滚和官方 API 幂等重放不发布重复变更。临时日志不进入持久结构或备份，本次无需数据库迁移。进程重启后客户端重连并重新查询，不依赖事件历史回放。仍应保持单个应用写入进程；其他连接直接修改业务表不会进入此连接的临时日志。

客户端将实时事件和操作后的刷新合并到 200 毫秒窗口，同一查询仅保留一个在途请求和一次后续刷新。隐藏页面暂停普通查询及断线兜底，恢复前台后统一同步；失权处理不等待页面可见。旧格式或未知事件回退为当前已打开模块的合并同步，旧客户端仍能读取 `revision` 事件。系统设置没有未保存输入时自动同步；有草稿时保留输入，在提交遇到版本冲突时才询问是否覆盖本次提交对应的设置，取消则继续保留草稿。页面不提供专门的重新加载按钮，需要最新内容时由用户手动刷新。

反向代理应允许 SSE 长连接，避免缓冲事件。构建后运行 `npm run test:realtime-http`，使用独立临时数据库检查多用户投递、跨机器原子修改、回滚静默和撤权；`npm run test:production-http` 检查生产 HTTP 与官方 API。浏览器验收应检查无关机器和日期无额外查询、隐藏与恢复、断线重连和编辑草稿保留。

系统设置与会话读取的单次等待上限为 15 秒（包含响应体读取）。读取失败按 2、5、15、30 秒退避重试，后续保持 30 秒间隔；隐藏页面暂停实际查询。首次设置未完整加载前不开放表单，保存和覆盖确认期间暂停编辑。保存前发出的查询不能覆盖保存后的结果，收到低版本或不完整数据会重新读取。网络错误不会被当成账号退出；权限复核失败时，受限内容继续隐藏。

设置写操作不会自动重发。写入超时、断线或服务端错误使结果无法确认时，保留输入并禁止继续提交，需手动刷新页面核对。明确的版本冲突返回 409，只有用户确认后才携带 `overwrite: true` 提交；该选项仅适用于内部系统设置接口，仍要求系统管理员权限、CSRF 校验和字段校验，并在事务中写入和记录审计。构建后可运行 `npm run test:settings-network` 做浏览器故障注入：需要可用的 Playwright 与 Chromium；可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 包路径、`PLAYWRIGHT_CHANNEL` 指定浏览器通道（如 `msedge`）。脚本使用隔离数据库，覆盖慢响应、首次部分失败、旧响应迟到、保存响应丢失、取消与确认覆盖、确认期间再次修改、跨表单草稿、离线与后台暂停、超时恢复及失权复核失败。

日历草稿预览通过合并队列按相关机器和时间范围刷新，单次读取上限 15 秒，失败 5 秒后重试，后台标签页暂停实际查询。预览结果仅应用于发起请求时的草稿，时间输入中不替换内容。内部日历预览和提交使用 `autoAdjust: true`，按可用区间自动裁切、拆分并通知用户；最终调整与创建、旧占用替换处于同一个即时事务。没有可用片段、超过 100 条、旧记录变化或写入失败不会释放原占用。官方 `/api/open/v1` 仍按既有确认令牌与冲突规则处理，不启用此自动调整。构建后可运行 `npm run test:calendar-adjustment` 做隔离浏览器验收，Playwright 配置同上。

文档中心的脚本和样式仅在访问 `/docs` 时加载，普通页面不预先下载完整手册。加载超过 15 秒或资源请求失败时，点击“重试”会重新加载当前地址，保留章节和锚点。构建后可运行 `npm run test:docs-loading`，检查按需加载、中英文与窄屏、历史导航，以及脚本、样式失败和超时后的重试；Playwright 配置同上。

页面入口及无版本静态文件使用 `no-cache` 和 ETag 校验，未变化时返回 `304` 并复用浏览器缓存。带内容哈希的 `/assets/` 文件缓存一年（`immutable`），版本变化后通过新文件名下载；仅下载变化的文件。业务 API 保持 `no-store`，不会缓存占用或权限数据。缺失资源返回不缓存的 `404`，不会将 HTML 当成脚本返回。代理应保留这些缓存头，不能对所有路径统一设置长期缓存。已有标签页不会因发布而自动刷新；重新打开或刷新页面时检查新版。构建后可运行 `npm run test:browser-cache` 检查实际浏览器缓存命中，Playwright 配置同上。

## 管理员密码恢复

```text
npm run admin:reset-password
```

此命令应只在服务器本地执行。恢复完成后立即登录、修改临时密码并检查审计记录。

## 安全基线

- 对外服务优先使用 HTTPS，避免会话 Cookie 经明文网络传输。
- 限制数据库、实例密钥和环境文件只允许运行用户读取。
- 不在日志中记录密码、`Authorization`、确认令牌或请求正文。
- 定期检查 401、403、409、429、5xx、响应耗时、邮件失败和备份结果。
- 个人访问令牌默认可长期有效，应建立定期盘点和吊销流程。

## 审计记录查询

数据库版本 21 仅增加审计查询索引，不重写历史记录，也不修改业务审计写入机制。版本 20 可原地升级；升级前备份数据库，降级时恢复兼容旧版本的升级前备份。列表、筛选选项和详情使用 `/api/v1/admin/audit` 下的内部接口，仅系统管理员可访问；官方 API 不变。列表只返回安全摘要，详情按需读取。本次不增加留存清理或导出策略。构建后可运行 `npm run test:audit-http`，验证隔离 HTTP、权限、中英文布局和网络失败；Playwright 配置同上。

## 机器公告

机器信息页提供独立的“机器公告”编辑入口。系统管理员和对应机器的管理员可以编辑，普通成员只读。每台机器保存一条纯文本公告，最多 2,000 个字符；支持多行正文，统一换行符并去除首尾空白，清空后保存即移除。日历展开机器时在资源组上方显示公告第一行，超长或后续内容以省略号表示，点击可查看保留换行的全文；实时更新不会替换编辑草稿或日历占用草稿。公告不发送通知或邮件。

数据库版本 22 增加 `machines.announcement`，现有机器默认为空公告。独立保存接口 `PUT /api/v1/admin/machines/:id/announcement` 接收 `announcement` 和 `expectedVersion`，在同一事务中检查版本、更新公告及机器版本、记录 `MACHINE_ANNOUNCEMENT_UPDATE` 审计并递增排期修订。其他机器资料保存不覆盖公告，官方 API 不变。构建后运行 `npm run test:machine-announcement`，验证隔离浏览器中的日／周视图、长文本截断、主题与窄屏、实时全文、草稿保留、冲突取消与覆盖、重复提交和权限撤销；Playwright 配置同上。
