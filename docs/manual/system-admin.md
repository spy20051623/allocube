# 系统管理员指南

系统管理员负责账号、机器、全局规则、邮件、统计和审计。

## 用户管理

系统管理员可以：

- 审核、退回或拒绝注册申请。
- 审核姓名和工号修改申请。
- 停用、重新启用或永久删除用户。
- 为已启用用户生成一次性密码重置链接。
- 查看账号状态、机器关系和最近登录信息。

停用用户会在同一事务中撤销其会话、个人访问令牌和待提交 API 操作。永久删除前应查看影响预览；占用和审计等必要历史会保留，并以去标识化名称显示。

## 机器与资源

系统管理员可以新建、修改、停用、重新启用和永久删除机器，并配置机器管理员。

资源项和资源组支持排序、版本和历史快照。停用或删除前必须查看影响预览；历史占用不会因资源删除而失去必要的快照信息。

## 使用权和机器管理员

- 使用权决定用户能否查看并占用机器资源。
- 机器管理员身份附着在机器使用权上。
- 只有系统管理员可以授予或取消机器管理员身份。
- 用户退出或失去机器使用权时，不能继续保留该机器的管理员身份。

## 停用与维护

临时不可用应使用维护；无限期不可用应使用停用。两者都会预览并处理受影响占用，但语义不同：

- 维护具有明确时间窗口。
- 停用持续到管理员重新启用。
- 永久删除用于确认对象不再需要，且不可恢复。

## 系统设置

“管理 → 系统设置”包含：

- 最短占用时长、单次最长时长和最远可占用天数。
- 站点地址，用于邮件中的查看和密码重置链接。
- 注册是否允许不填写邮箱，以及允许注册的邮箱域名。
- SMTP 服务器、端口、安全模式、账号、密码和发件人。
- ICP 备案号与公安联网备案号；有效值显示在登录等认证页面底部，并链接到对应查询页面，留空则不显示。

修改全局规则不会自动重写已有占用。站点地址必须是完整的 HTTP 或 HTTPS 来源，不能包含业务路径、查询参数或片段。

未编辑时，设置会自动同步其他页面或设备的更新；有未保存输入时保留草稿。提交时若数据已更新，会询问是否覆盖本次提交对应的设置：确认后保存，取消则返回草稿。需要重新查看最新设置时，请自行刷新浏览器，刷新会丢弃未保存输入。网络异常导致保存结果无法确认时，不会自动重发，请手动刷新后核对。


除日历外，机器资料、资源配置、公告和反馈编辑采用相同的冲突处理：未修改时同步最新内容，已修改时保留草稿，提交过期版本时确认是否覆盖。确认只覆盖本次提交对应的数据，不跳过权限、字段、容量或工作流状态检查；已删除的对象、已处理的申请以及只读反馈不能强行修改。审批、启停和维护的版本或影响范围过期时，也需要确认后才能按当前数据执行。

## 系统公告

系统公告用于向所有可登录用户展示重要通知。进入“系统公告”后，可以创建、编辑和预览公告，并随时撤下仍在展示的公告。列表默认只显示仍在展示的公告；打开“显示已撤下”后可以查看历史公告，并通过同一个编辑器修改内容后重新启用。

公告标题最多 120 个字符，正文最多 10,000 个字符。正文支持常用 Markdown，包括段落、列表、引用、表格、代码和链接；原始 HTML 与图片不会渲染。

链接统一使用 Markdown 写法：

```markdown
[查看外部说明](https://example.org/help)
[查看资源日历](allocube:/calendar)
```

- `https://` 或 `http://` 表示外部链接，并在新窗口打开。
- `allocube:` 表示站内跳转，其后必须是 Allocube 已知页面的绝对路径，例如 `allocube:/calendar`、`allocube:/profile` 或 `allocube:/docs/api`。
- `javascript:`、未知站内路径和其他协议不会生成可点击链接。

多个有效公告按发布时间依次展示。编辑或重新启用会生成新版本，并把发布时间更新为保存时间，因此看过旧版本的用户仍会收到新版本。用户关闭公告后，浏览器会按“用户 + 公告版本”记录已展示状态，同一浏览器中不再重复显示同一版本；该状态不会跨设备同步。撤下会立即停止公告继续展示，但不会删除公告及其审计记录。

## 处理反馈

在“管理 → 反馈处理”查看全站问题单和需求单，可按类型、状态和级别筛选，回复评论、调整级别，并填写处理说明后更新状态。问题单使用“已确认／已修复”，需求单使用“已采纳／已实现”；两者均可拒绝。系统保留处理活动和审计记录。已撤回反馈完全只读，不能重新开启；机器管理员身份不授予全站反馈管理权。

## 邮件发送

SMTP 启用后，注册验证码、密码重置和事件提醒进入持久化发件箱。失败任务会重试，管理页会显示队列、最近错误和测试结果。

新注册、资料变更和机器使用权申请不再逐条发送即时管理员邮件。服务启动时检查一次，之后按每 30 分钟边界检查：仍待处理且等待超过 15 分钟的申请按管理员汇总为一封邮件，同一管理员对同一申请版本只提醒一次。系统管理员接收全站相关待办，机器管理员仅接收所管理机器的使用权待办；需有可用邮箱并开启“超时待办”。

验证码、密码恢复及账号阻断类必要邮件继续发送；影响排期的邮件由用户的“排期影响”设置控制。普通反馈更新和常规业务通知只在站内展示。

SMTP 密码使用实例密钥加密保存，页面和接口不会回显明文。更换或丢失 `instance-secrets.json` 后，需要重新输入 SMTP 密码。

## 使用统计

使用统计每天北京时间 06:00 结算上一自然日，页面读取已保存的结果，不实时重新计算。统计基于系统登记的占用时段，不代表真实硬件利用率。

日期筛选固定使用北京时间，开始和结束日期均包含在内，默认最近 7 个应结算日期。06:00 前最新应结算日期为前天，之后为昨天；当天不提供统计，与日历的时区显示切换无关。页面显示统计截至日期；修改日期或机器后，点击“刷新统计”才应用筛选并读取结果。

跨天占用按每日覆盖的时间分摊；多日查询的有效占用数按占用去重。整机占用分别计入相关资源组的占用时长，但用户排行中的时长只计算一次。占用率按汇总时长计算，不平均每日百分比。

首次升级会后台补算全部已有历史，近期日期优先。查询直接汇总所选范围内已有的统计结果，无结果的日期按 0 忽略，不显示待统计日期提示；整个范围都没有结果时显示 0。历史补算依据现存记录，不能还原已删除或改变的历史配置。

系统管理员可使用页面右上方的“全部重新统计”，确认后重算全部机器与历史日期，不受当前筛选影响。任务在后台继续运行，关闭页面不会取消；重算期间旧结果仍可查询，全部完成后统一切换，失败保留旧结果。页面显示任务进度，重复提交不会并行创建任务。普通用户和机器管理员没有此入口。

日常占用变更不自动修改已结算数值；需要更新历史结果时由系统管理员全量重算。读取统计仍使用当前机器使用权，删除的用户或资源继续匿名展示。

## 审计记录

审计记录仅系统管理员可查看。按操作日期、操作者、操作类型和来源筛选，点击“查询”后生效；“重置”清空条件并重新查询。日期按当前时区模式解释，包含起止日期，筛选的是操作发生时间。

记录按时间倒序展示，每页 50 条，可以查阅全部保留的历史。翻页沿用本次查询的记录边界，新增记录在重新查询后出现；返回第一页也不会打乱原来的分页。页面不自动轮询更新。加载失败保留已显示记录，可点击“重试”。

点击记录查看只读详情，包括完整标识、已有的修改前后变化、原因和关联信息。占用对象尽可能展示机器、资源组或整机范围及历史载荷中记录的时段。对象名称使用当前资料，缺少的历史值不会用当前业务值补填；批量操作仍保留逐条记录。

来源“个人 API”依据已记录的令牌或 API 操作标识判定，详情显示现有令牌名称和操作标识。其他来源统一显示“其他”，不推断旧记录是否来自网页。密码、令牌明文、SMTP 密文和管理备注正文不提供给审计页面。删除用户和资源继续去标识化，相关详情可能隐藏；未记录或无法读取的历史内容不会影响其他记录。
