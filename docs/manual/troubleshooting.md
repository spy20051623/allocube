# 故障排查

## 请求来源不受信任

网页修改请求要求同源。常见原因：

- 页面和 API 使用了不同协议、域名或端口。
- 在 `localhost` 与 `127.0.0.1` 之间切换。
- 反向代理没有正确传递 `Host`、`X-Forwarded-Host` 或 `X-Forwarded-Proto`。

不要关闭 Origin 或 CSRF 校验，应修复访问地址和代理配置。

## 登录后立即退出

检查：

- 系统时间是否正确。
- 登录会话是否已经到期。
- 账号是否被停用。
- 浏览器是否允许当前站点 Cookie。
- HTTPS 终止后协议头是否正确传给应用。

## 看不到机器或资源组

- 在“全部资源”确认机器状态和自己的使用权。
- 检查使用权申请是否仍待审核。
- 确认机器或资源组没有被停用或删除。
- 机器管理员只能管理被授权机器。

## 我的占用中找不到定位入口

“我的占用”位于日历标题右侧。“已结束”分组包含已取消记录，但已取消记录不提供定位；机器或资源组已删除、或已失去机器使用权时也不能定位。资源组筛选需先选择机器，切换机器会清空原资源组筛选。

## 编辑序列已变化或提交结果不明确

旧占用被管理员调整、取消或已经结束时，编辑序列会失效；已填写的草稿保留，需要核对后放弃本次编辑并重新选择。收到明确冲突或校验失败时，整批修改不生效。若请求发生网络异常，先查询最新记录判断是否已经提交，不要将结果不明确当作一定失败并直接重试。

## 占用提交时冲突

预览和最终提交之间，资源状态可能变化。服务端会在事务中重新检查；收到冲突时刷新日历，根据最新结果重新选择，不要反复提交旧草稿。

## 占用因维护变化

维护或停用可能取消、裁切或拆分占用。查看通知和占用详情中的调整原因。取消维护不会自动恢复已调整占用，需要重新创建。

## 收不到邮件

系统管理员应检查：

- SMTP 是否启用且状态为可用。
- 服务器、端口、安全模式、账号和发件人是否匹配服务商要求。
- 测试邮件结果和持久化发件箱最近错误。
- 站点地址是否正确。
- 用户邮箱是否完成验证，域名是否在允许列表中。

邮件关闭时，站内通知仍然工作。并非每条站内通知都发送邮件：常规业务和反馈更新通常只在站内展示。管理员审核邮件是超过 15 分钟未处理的待办摘要，按每 30 分钟检查一次，且同一申请版本不会向同一管理员重复提醒；同时检查用户的“排期影响／超时待办”开关。

## 密码重置链接无效

链接一次有效，签发后 30 分钟到期。重新申请新链接；没有绑定邮箱时联系系统管理员。密码重置后旧网页会话失效，但个人访问令牌仍需单独处理。

## API 请求失败

先读取响应中的 `error.code`、`error.message` 和 `error.requestId`，再按 HTTP 状态处理：

| 状态 | 常见原因 | 处理方式 |
|---|---|---|
| `400` | 参数、时间、请求体或占用片段不符合约束，或请求包含未知字段 | 按当前 OpenAPI 修正请求，不要原样重试 |
| `401` | `Authorization` 缺少 `Bearer`，令牌不完整、无效、到期或已吊销，或账号已停用 | 更正认证信息或创建新令牌；网页 Cookie 不能用于官方 API |
| `403` | `INSUFFICIENT_SCOPE` 表示只读令牌执行写操作；`FORBIDDEN` 表示没有目标机器使用权或目标占用不属于本人 | 使用具备写权限的令牌，或重新确认机器使用权和占用所有者 |
| `404` | 目标不存在，或出于隐私保护不能向当前用户确认目标是否存在 | 检查 ID 和访问范围；不要据此推断他人的资源或占用 |
| `409` | 预检后权限、资源配置或占用状态发生变化，或操作已经失效 | 丢弃旧确认令牌，刷新数据并重新预检 |
| `410` | 确认令牌已超过 5 分钟有效期 | 重新预检并使用新令牌提交 |
| `429` | 超过整体请求限制，或预检与提交的单独限制 | 读取 `Retry-After` 并等待；降低轮询和并发频率 |

端点的完整状态码和具体失败原因以[官方 API](/docs/api)中的动态 OpenAPI 端点参考为准。

## 生产首次启动因管理员密码失败

检查日志是否指出 `BOOTSTRAP_ADMIN_PASSWORD` 缺失或不符合规则，并确认进程以 `NODE_ENV=production` 运行。直接启动读取工作目录的 `.env`，Docker Compose 使用 `.env.production`。修正配置后沿用同一数据库目录重启，不要删除已生成的空结构或实例密钥；已有实例改密码需使用登录后的密码修改或服务器端恢复命令。

## 使用统计缺少最近日期或重算失败

当天不参与统计；北京时间 06:00 前通常只统计到前天，之后到昨天。首次补算或停机恢复期间可能显示待统计日期，这些日期不是零占用；等待完成后刷新页面即可导出 CSV。刷新按钮不会触发重新计算。

全量重算由系统管理员在标题旁发起。任务失败时旧统计仍可使用，检查服务器日志、磁盘空间和数据库权限后可再次发起；关闭页面不取消任务，服务重启会续跑未完成任务。提交时发生网络错误，应先核对任务状态，不要连续重复点击。

## 健康检查失败

`/health` 返回 `503` 通常表示数据库不可用。检查数据库路径、文件权限、磁盘空间和 SQLite 文件是否位于本地持久磁盘。恢复前先保留故障现场并验证备份。
